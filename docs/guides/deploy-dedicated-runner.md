# How to deploy a dedicated Aster Team Runner

[简体中文](../zh-CN/guides/deploy-dedicated-runner.md) · [Deployment guides](README.md) · [Architecture](../architecture.md)

A dedicated Aster Runner executes approved model requests from a customer-controlled host. It connects outbound to Control over WSS and to configured AI providers over HTTPS, so the Runner host does not require an inbound listening port.

## When to use a dedicated Runner

Use a separate Runner when the team needs a distinct network path, host security boundary, fault domain, or additional request capacity. A same-host Runner remains appropriate for a small deployment.

A Runner host is trusted with the prompts and responses it processes. Restrict operating-system administration to authorized personnel and place the host within the required data and network boundary.

## Install the Runner

Use a signed package compatible with the Runner platform and the Control release. On Linux:

```bash
sudo ./init.sh
sudo aster-team-cli runner install
```

On Windows, run `init.ps1` as Administrator and then run the installed CLI command printed by the script with `runner install` appended.

## Enroll the Runner

1. In **Admin → Runners**, choose the target platform and create a one-use enrollment token.
2. Save the token to a file readable only by the operating-system administrator. Use mode `0600` on Linux; on Windows, grant access only to Administrators and SYSTEM.
3. Run the enrollment command generated by Admin. It uses `--token-file`, keeping the token out of command history and process arguments.
4. Confirm that the Runner appears online and run **Test connectivity**.

The enrollment token can be used once and expires. Create a new one instead of reusing a failed or previously completed enrollment token.

## Configure Control trust

- For a public-CA HTTPS Control address, the Runner uses its built-in WebPKI trust store.
- For an internal CA, pass the public CA certificate through the generated `--control-ca-certificate` option.
- For a trusted-LAN HTTP address, use the explicit `--allow-insecure-http` option shown by Admin. Do not expose that path to an untrusted network.

The custom Control CA affects only Runner-to-Control registration and WSS. It does not change the CA trust used for outbound provider HTTPS connections.

## Understand routing

Runners are not permanently assigned to a subscription or account. Every enabled, online, protocol-compatible, healthy Runner with available capacity can become a routing candidate. Aster prefers useful recent affinity and can choose another healthy Runner before an upstream request begins.

Once a streaming response has started, Aster does not silently migrate that request to a different Runner. This prevents an ambiguous replay from being presented as the original stream.

## Diagnose `RUNNER_NOT_READY`

```bash
sudo aster-team-cli runner status
sudo aster-team-cli logs runner
sudo aster-team-cli logs control
```

Check Runner enablement, protocol compatibility, heartbeat freshness, capacity, DNS, TLS, firewall, proxy settings, and outbound provider connectivity. `RUNNER_NOT_READY` (`33003`) means no candidate met all routing conditions; the rejected request is not charged.
