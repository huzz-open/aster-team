# Use Codex through Aster

[简体中文](zh-CN/codex.md) · [Documentation](README.md)

Aster can act as a custom Responses API provider for Codex in the ChatGPT desktop app and for Codex CLI. This does **not** redirect ordinary ChatGPT web conversations: the regular ChatGPT chat interface does not expose an arbitrary API base URL.

Codex officially supports custom model-provider definitions with a provider `base_url`, an `env_key`, static headers, and the `responses` wire API. See OpenAI's [Codex configuration reference](https://developers.openai.com/codex/config-reference/).

## Before setup

1. Install the official ChatGPT desktop app or Codex CLI appropriate for your environment.
2. In Aster Member UI, create your personal API key.
3. Open **API documentation → asterctl tool**, download the artifact matching your device, and run the one-line installation command shown there.
4. Fully exit Codex before changing its configuration.

On Windows, OpenAI distributes Codex in the ChatGPT desktop app. Use the [official Windows app guide](https://developers.openai.com/codex/app/windows/) or install the same Microsoft Store product from PowerShell:

```powershell
winget install --id 9PLM9XGG6VKS -s msstore
```

Seeing the application name **ChatGPT** after installation is expected; this is not a separate Aster or third-party client.

## Recommended setup

Run the command generated by Member UI. A typical Windows example is:

```powershell
asterctl setup codex --base-url "https://aster.example.com/v1" --set-key --launch
```

Enter the member API key at the hidden prompt. `asterctl` validates the endpoint and key, stores `ASTER_API_KEY` for the current user, merges the Aster provider into the existing Codex configuration, verifies the effective provider, and optionally launches Codex. The key is not placed in command history or an Aster status file.

Omit `--launch` to configure without starting Codex.

## Inspect or remove the configuration

```powershell
asterctl status codex
asterctl doctor codex
asterctl remove codex
```

`remove codex` restores fields still matching values written by `asterctl` and preserves unrelated or subsequently changed settings. It intentionally preserves `ASTER_API_KEY`; remove that user environment variable separately if it is no longer needed.

## Advanced manual configuration

Use this only when `asterctl` is unavailable or when diagnosing configuration. Store the member API key as a user environment variable, then place this provider configuration at the top level of the Codex `config.toml`:

```toml
model_provider = "aster"

[model_providers]

[model_providers.aster]
base_url = "https://aster.example.com/v1"
env_key = "ASTER_API_KEY"
name = "Aster Team"
wire_api = "responses"

[model_providers.aster.http_headers]
x-openai-actor-authorization = "aster-proxy"
```

On Windows the default file is `%USERPROFILE%\.codex\config.toml`. If `CODEX_HOME` is set, use that directory instead.

`ASTER_API_KEY` is the credential. The `x-openai-actor-authorization` value is a non-secret compatibility marker; it does not replace API-key authentication. This setup does not require `OPENAI_API_KEY` or `OPENAI_BASE_URL`.

## Model catalog behavior

`asterctl` preserves the existing catalog, adds Aster-managed fast entries when supported, and does not change the default model. Actual availability still depends on models enabled by the Aster administrator and on upstream capabilities. Run setup again after a Codex catalog upgrade to refresh the merged catalog without re-entering the key.
