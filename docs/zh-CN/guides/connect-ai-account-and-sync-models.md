# 如何在 Aster Team 中连接已授权 AI 账号并同步模型

[English](../../guides/connect-ai-account-and-sync-models.md) · [部署指南](README.md) · [管理员指南](../admin-guide.md)

本指南介绍如何把客户有权使用的 AI 账号或订阅连接到 Aster Team，同步可用模型，并通过独立成员 API Key 开放管理员选定的模型。

## 前置条件

- 组织拥有该账号，或已经取得使用授权。
- Aster 产品 License 包含所需的账号接入与 Runner 能力。
- 至少一个兼容 Runner 在线。
- Runner 可通过组织批准的网络路径访问上游认证和模型端点。
- 管理员已经了解上游服务的用量限制、费用和条款。

连接 ChatGPT 订阅时，Runner 需要通过 HTTPS 访问 `auth.openai.com` 完成授权刷新，并访问 `chatgpt.com` 同步模型和执行请求。

## 连接账号

1. 登录管理端并打开“订阅/账号”。
2. 选择“添加账号”，启动 OAuth 授权流程。
3. 使用客户已授权的上游账号登录并同意所需访问。
4. 返回 Aster，确认账号状态健康。
5. 为逻辑账号设置便于管理员识别的名称，不要把密码或秘密值用作名称。

上游凭据仍由管理员控制。开发者获得的是 Aster 成员 Key，而不是上游密码、浏览器会话、Access Token 或 Refresh Token。

## 同步并启用模型

1. 选择已连接账号，执行“同步模型”。
2. 检查返回的模型目录与账号健康状态。
3. 只启用团队获准使用的模型。
4. 创建或启用成员并发放额度。
5. 让成员创建个人 API Key，并查询 `GET /v1/models`。

公开模型列表只包含管理员启用的模型。上游已经同步的模型不会自动向所有成员开放。

## 在不分发上游凭据的情况下增加容量

一个逻辑账号可以包含多个独立完成授权的凭据实例。每个实例都必须来自一次单独完成的授权流程。复制同一个 Refresh Token 不会形成独立容量，并会被识别为重复凭据。

健康 Runner 组成共享路由池。凭据不会永久绑定某个 Runner；Aster 会为每次请求选择符合条件的执行路径。

## 常见问题

- **OAuth 会话无效或过期：** 重新发起授权，不要复用旧回调。
- **同步模型失败：** 检查 Runner 健康状态及 DNS/TLS 出站访问，然后在已有账号上重试同步。
- **成员看不到模型：** 确认模型已显式启用，并使用有效成员 Key 查询 `/v1/models`。
- **`MODEL_ACCOUNT_NOT_READY`（`33002`）：** 模型存在，但当前没有可用凭据实例。
- **`RUNNER_NOT_READY`（`33003`）：** 当前没有 Runner 同时满足健康、兼容、心跳和容量条件。

账号、网络、权益和上游责任见[服务边界](../service-boundaries.md)。
