# 如何用一个已授权 AI 订阅运行多个独立 Codex 客户端

[English](../../guides/multiple-independent-codex-clients.md) · [开发者指南](README.md) · [服务边界](../service-boundaries.md)

Aster 把客户已有并获授权的 AI 能力转化为面向开发者的独立、可治理访问路径。它不会向成员分发上游服务的密码、会话、Cookie 或账号凭据；每位开发者都使用独立的 Aster 成员 API Key。

```text
客户已有并获授权的账号或订阅
              │
              ▼
      Aster Control + 客户 Runner
          │          │          │
          ▼          ▼          ▼
       开发者 A    开发者 B     CI 任务
       成员 Key     成员 Key     成员 Key
       独立额度     独立额度     独立额度
       独立用量     独立用量     独立用量
```

## 部署流程

1. 管理员连接组织有权使用的账号或订阅。
2. 客户自建 Runner 上线，并同步管理员启用的模型。
3. 管理员创建成员并按团队策略发放额度。
4. 每位成员登录成员端，创建自己的 Aster API Key。
5. 每位开发者在自己的设备或操作系统账号下运行 `asterctl setup codex`。
6. 管理员可以查看用量、调整额度或单独撤销某个成员 Key，而无需向成员分发上游凭据。

## “独立”具体指什么

- **身份：** 每位开发者使用独立的 Aster 成员和 Key。
- **额度：** 按成员判断发放额度与可用余额。
- **计量与审计：** 请求归属到实际发起请求的成员路径。
- **撤销：** 可单独撤销一个 Key，无需轮换所有开发者凭据。
- **本地 Codex 状态：** 使用不同设备、操作系统用户或 `CODEX_HOME` 时，本地历史和配置可以相互分离。

在同一台电脑运行多个客户端时，优先使用不同操作系统用户。高级用户也可使用不同的 `CODEX_HOME` 和进程环境，但必须自行确保 Key 与历史不会跨会话复用。

## Aster 不负责隔离的部分

- 上游服务会按照客户已授权账号及其自身政策处理请求。
- Runner 主机管理员能够查看该 Runner 处理的 Prompt 和响应。
- 使用相同操作系统用户与 `CODEX_HOME` 的 Codex 会话可能共享本地配置和历史。
- 网络设施与运行日志仍由客户负责安全和保留策略。
- Aster 的独立访问路径不会创建更多上游账号、订阅、积分或权益。

该架构用于组织内部的授权使用，不用于转售凭据或绕过限制。部署前请阅读[服务边界](../service-boundaries.md)、[访问隔离说明](developer-access-isolation.md)以及相关上游服务条款。

## 常见问题

### 这等于共享上游账号密码吗？

不等于。成员只获得 Aster Key。上游凭据仍由管理员控制，并且只通过客户自建网关路径使用。

### 每位开发者都会得到独立的上游账号吗？

不会。Aster 只基于客户已有能力创建独立治理路径，不会创建上游账号。

### 一位开发者会消耗另一位开发者的额度吗？

请求会计入完成认证的成员路径。请保护每个成员 Key，不要在多人或多个自动化身份之间复用。
