# 服务边界与客户责任

[English](../service-boundaries.md) · [中文文档](README.md)

Aster Team 是用于私有化运行和治理受支持 AI 服务访问的软件。它将客户有权使用的账号接入客户自行运行的基础设施，并不销售或提供这些第三方服务。

## Aster 提供的能力

- 私有化部署的模型 API 网关与控制平面。
- 接入客户有权使用的第三方账号或订阅。
- 独立的成员身份和 Aster API Key。
- 模型访问策略、额度分配、用量记账和审计记录。
- 由客户运行的 Runner，通过批准的网络目的地执行受支持的模型请求。
- 兼容 OpenAI、Anthropic 的接口及已经说明的客户端接入方式。

## Aster 不提供的内容

- 第三方账号、订阅、API 额度、模型权益或账号注册服务。
- 通用 VPN、互联网接入、网络出口或跨区域网络接入服务。
- 绕过身份验证、地域限制、组织策略、服务商控制、速率限制或服务条款的机制。
- 对特定服务商、账号、模型、功能或地区持续可用的保证。
- 使用第三方服务所需的法律、监管、税务或合同授权。

## 账号、订阅与费用

“订阅/账号”页面用于连接客户已经控制的账号。Aster 不创建、转售、转移或捆绑这些账号。客户负责确认账号所有权或使用授权、订阅状态、上游费用以及对服务商条款的遵守情况。

Aster License 只控制 Aster 产品权益，不购买或扩大上游模型访问权，也不能替代服务商要求的订阅、账号或用量费用。

## 网络责任

Aster 通过客户自行运行的 Control 和 Runner 转发受支持的模型 API 请求。客户需要为每个 Runner 准备合法且获准的上游连通条件，包括 DNS、TLS 信任、防火墙规则以及组织批准的网络出口配置。

Runner 是面向特定应用的执行组件，不是通用网络转发设施。Aster 不提供 VPN、通用代理、跨区域连接或访问限制规避服务。如果某个服务商在客户环境中不具备法律或技术上的可用条件，部署 Aster 不会使其变得可用。

## 可用性与兼容性

实际能力同时取决于四个相互独立的层面：

1. Aster License 权益。
2. 管理员策略及已开放模型。
3. 客户账号或订阅本身的权益。
4. 服务商可用性、兼容性与网络可达性。

Aster 文档中列出的接入方式表示 Aster 支持对应协议或客户端流程，并不代表第三方服务商背书，也不保证覆盖上游的全部功能。

## 客户检查清单

接入账号或向成员提供平台地址前，应确认：

- 组织有权使用该账号和服务；
- 部署地区与网络路径符合适用要求；
- 已了解上游费用与限制；
- 只有客户控制的 Runner 主机能够接触请求内容；
- 成员 Key、日志、备份和账号凭据均按敏感数据处理。
